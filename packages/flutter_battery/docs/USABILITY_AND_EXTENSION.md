# 功能可用性与扩展顺序

本评估基于当前工作区，不代表发布版本。验收矩阵、构建、真实运行和人工界面各自解释。

| 范围 | 当前结论 | 主要缺口 |
| --- | --- | --- |
| macOS 核心读取、供电/充电、独立观察 | 可受控使用；已有原生运行与状态测试 | 真正无电池宿主、长期运行、前后台与引擎重建 |
| Android 核心 | 已有构建；逻辑状态覆盖 | 真机、电源切换与厂商差异验证 |
| 桌面 Battery Lab | 可用；真实创建/关闭会话，筛选日志与响应式布局 | 持久历史、会话恢复、完整键盘操作 |
| 通知 | 独立接口，宿主管权限 | Android 拒绝/撤销/延迟通知实际验收；macOS 不支持 |
| BLE/peer | 部分旧接口存在 | 特征通知未实现，外设及角色生命周期验收不足 |
| Windows/iOS/Web 核心 | 未实现，返回不支持 | 平台接入与独立验收 |

## 扩展性判断

核心具备可注入的平台接口、统一结果和需求协调器，可以增量扩展。新增可选信息不需要扩大核心操作数量；新增平台仍需同步原生注册、宿主平台判断与平台矩阵。多处 enum/switch 和 legacy 通道需要同步维护；纯粹增加按钮不能补齐原生能力。

## 本轮独立推进的核心能力

- 容量诊断为可选 BatteryCapacityDetails，携带 remaining/fullCharge/design/cycleCount/unit/source。
- macOS 读取明确 AppleRaw 原始容量字段，不把 MaxCapacity=100 的百分比与 DesignCapacity 原始数值混用。公开接口未确认物理单位时标为 unspecified，不计算设计容量百分比。
- Android 只使用公共 BatteryManager charge counter，通过 getLongProperty 区分不支持与真实零值，微安时换算为整数毫安时；不伪造满充/设计容量和循环次数，不读取权限不明的 sysfs。
- 缺失诊断保持空；真实 remaining=0 与 cycleCount=0 保留，非法负数与单位返回 invalidData。
- 示例显示实际容量、循环与来源，明确未知单位。失败会话显示异常，仍可关闭，不再误计为活跃会话。

## 后续顺序

1. 先收齐 Android 真机、电源切换、关闭恢复、长时间稳定性与测量单位证据。
2. 再选择首个平台/可选能力：Windows 电池适配、Android 通知、BLE/peer 三者分开推进。
3. Windows 若被选定，先接入基础电源状态与无电池分支，再补容量/健康；当前 macOS 主机不能把 Windows 构建或设备验收标为通过。
4. 通知与 BLE 继续独立于核心电池 API，保留拒绝、撤销、重试与退出的明确结果。

用户已选择“核心扩展 + 平台/可选能力”；第二类的首个目标仍待具体选择。等待期间仅推进不依赖该选择的核心诊断与可用性修复。
