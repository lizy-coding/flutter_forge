# Forge GenUI 模块探索改造范围

日期：2026-10-23。状态：用户已批准实施，首页入口和真实模型闭环已落地；验证与已知限制见 [接入记录](reports/GENUI_MODULE_DISCOVERY-20261023.md)。本文替代此前扩大为教学体系与跨场景训练的计划。

## 用户目标

把 GenUI 融入 Forge 的模块检索与选择，通过实际改造理解 GenUI 并丰富项目。用户以未来餐厅智能点餐类比：表达需求，在真实可选范围内获得合适且可操作的推荐。

不建设知识库、课程体系、能力图谱或通用 Agent 应用；不以扩充模块数量、完成独立考题或实现多会话管理作为接入前提。

## 核心链路

用户表达学习意图 → 模型读取精简的真实模块清单与允许的组件描述 → 生成推荐、理由、分组／对比布局或澄清选项 → GenUI 渲染 → 用户选择或继续澄清 → 更新推荐或经现有路由进入模块。

模型只引用现有模块。模块标题、简介、概念、难度、时长和平台支持来自注册元数据；卡片由本地数据渲染，模型不能创造模块、执行结果或任意跳转地址。没有合适模块时明确说明。

生成范围包含受限组件的选择、组织与更新，不能只有模型文字加固定搜索列表，也不要求生成 Dart 或任意代码。

## 最小工程范围

- 复用 ModuleEntry 与既有平台判定、路由；当前模块数量下可直接提供精简目录，不先维护大量问法规则或引入向量库。
- 新增面向模块探索的 Catalog：推荐说明、模块卡片、自适应分组／对比、澄清选项。当前 constraint-lab 专用目录和参数约束不能直接用于模块推荐。
- 推荐会话只管理学习意图、有限澄清、生成结构、请求与错误状态，不承担跨模块任务编排。
- openModule 动作由本地白名单解析后进入现有路由，不再次调用模型；需要重新理解意图的 refineIntent 动作才发出下一轮请求。
- 校验组件类型、树引用、模块标识、动作、数量和文本长度。取消和迟到结果隔离遵循常规请求生命周期。
- 复用已有 SDK 和传输模式，通用部分在应用组合层接入，不让学习叶子模块相互依赖。入口具体布局围绕现有检索细化，首版不直接替换整套导航壳。

## 模型与成本

个人本机实践沿用现有 Codex 登录桥接，不要求云服务器，不作为公共访客后端。用户已接受少量真实模型调用，联调前明确次数和等待预算。

提交意图和语义澄清按需调用模型；展开卡片和路由跳转本地执行。服务不可用时明确报错，并可使用原有本地模块浏览／检索，不能把回放称为真实生成。

## 验收

真实意图能得到引用真实模块的推荐；不同意图可以产生不同的组件组合或组织方式；至少验证一次澄清后的局部更新。布局随机变化不作为价值证明。

用户能从生成卡片进入对应模块；无匹配、非法引用、非法组件和模型服务失败不造成错误跳转。支持状态继续使用统一平台规则。通过观察真实消息、状态和动作学习实现，而非先完成脱离项目的考题。

## 后续边界

多会话管理是长期方向，用户已明确当前不要求。后台任务、任意 DAG、任务恢复和跨模块实验编排均不纳入本轮。

原约束实验与文章工作流继续保留，各自事实见 [GenUI 实施记录](reports/GENUI_WORKBENCH_IMPLEMENTATION-20261022.md) 和 [工作流基建](WORKFLOW_ECOSYSTEM_FOUNDATION.md)，不再指定为用户必须依次完成的训练路径。
