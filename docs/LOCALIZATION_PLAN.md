# 框架与目录国际化收尾方案

状态：2026-11-06收尾实现已接入，完整源码门禁、Android与Web构建通过；真实平台验收单独待执行。

## 当前决定

用户重新评估国际化收益后，选择“保留基础能力，收尾框架目录”。这取代此前要求35模块操作界面全部双语后才能发布的范围。仍采用官方 flutter_localizations、gen_l10n、ARB 与 workspace 内独立 forge_localization 包，暂不公开发布。

当期目标是框架和目录的完整双语入口，教学实验内部标题、操作按钮、公共章节与正文统一中文，框架导航和返回继续跟随界面语言；模块入口与实验页明确标注“中文实验”。以后按真实使用需求选择完整模块翻译。不以已有代码投入作为继续扩大翻译范围的理由。此前全模块方案保留在 [历史方案](localization/PLAN_FULL_MODULES-20261106.md)，不再作为当期验收要求。

- 独立包已实现语言解析、通知、串行保存和失败状态。宿主已有偏好存储和系统语言事件接入；多窗口同步未完成。
- 4008离线Release候选包在V2338A/Android16上已验证基本切换、重启保持、目录、gpu搜索、翻页和返回；一次意外分类跳转未稳定复现。不能据此声明切换路径全部通过。
- 实验页仍存在中文按钮、标题、教学文字，公共章节英文与中文正文混合。框架仍有探索面板、外观tooltip、隐私控制、预计时长和概念标签中文。
- 当前没有目标英语用户或反馈证据可证明全模块操作翻译的收益；这是证据缺口，不等于已经证明收益为零。

## 兼容策略建议

全平台复用同一语言和文案机制；现有响应式布局继续按可用宽度选择。英文长文案先换行或调整布局，仅按钮、标签页、表头可人工短标签，同时保留完整语义及提示；错误和权限说明不缩写。技术标识符、路由ID、URL、存储键不翻译。

中英当前均为从左到右语言，不为未知的更多语言预建RTL或区域特化系统。日期/数值只在实际本地化展示处使用明确的格式规则，实验参数、协议与代码样例保持其技术语义，不全局替换小数或日期字符串。

中文实验使用明确的模块范围表示语言，而不是允许某个控件因“翻译缺失”随机回退。官方Localizations.override可为子树指定Locale，但不会翻译硬编码文案，也不能替代业务层内容语言声明。具体落点先在一个模块验证，确保不会重启路由、实验或外设会话。

## 实施与发布顺序

1. 实现已确认的中文实验边界，补目录/模块语言说明，并消除公共章节英文与实验中文的混排。
2. 收尾框架遗漏：外观、隐私操作、探索控制、预计时长、全局错误与不可用提示。
3. 完成目录和中英搜索字段覆盖；维持稳定路由和历史记录。
4. 完成必要的多窗口语言同步与Web启动壳接入；宿主验收结果独立记录。
5. 修复或明确4008切换异常观察；检查默认跟随系统、手动选择、保存失败、重启、前后台与中文输入。
6. 执行既有质量门禁并构建新Android候选包；同签名升级和真机验收通过后满足当期国际化发布关口。35模块内部操作翻译不再阻塞当期；新发布日期仍按实际结果确定。

Android仍为本次发行真机关口。macOS/Windows/Web完成声明范围内代码接入与相应测试，其原生、多窗口和浏览器实测分别记录；iOS无宿主，不宣称已经宿主验收。

## 完成标准

- 承诺双语的框架和目录操作没有未声明中文残留，教学或外部内容语言可辨。
- 不以静默中文回退掩盖框架漏翻；原始日志、教学正文不纳入框架漏翻计数。
- 320/360dp及大字体定向检查，桌面导航保持可用；不为每种语言维护独立布局副本。
- 切换语言保持路由、搜索、目录位置及实验任务；默认与持久化策略沿用已确认规则。
- 目录支持声明与内容语言声明相互独立；不能因英文未翻译隐藏平台支持模块。
- 通过当期门禁与Android新候选包的真实操作检查；历史4008结果仅作为基础证据。

## 长期维护

新增全局/目录操作文案同步维护两份ARB与必要参数；模块内部中文改动不要求同步英文。将来提供完整双语模块时，以模块为单位声明已覆盖的操作与内容范围并做单独验收。通用包只维护语言机制，持续保持业务无关，不为它单独增加与当前目标无关的平台原生桥接。

## 已确认的语言边界

英文框架进入实验后，模块内部标题、操作按钮、公共教学章节与正文统一中文，应用框架的导航与返回继续跟随界面语言。目录入口和实验页都提供可辨识的“中文实验 / Chinese experiment”语言说明，不宣称模块已双语化。

局部Locale边界要覆盖主实验页及其内部子路由，不能只包入口Widget而让子页面恢复英文。教学弹窗/菜单属于实验，跟随中文；框架搜索、目录、设置和不可用说明仍属于框架，跟随应用语言。实现需验证浮层继承与返回栈，并保持当前路由、实验控制器和外设会话实例。

这些边界是产品约定；Localizations.override只是可采用的实现手段，不能把它的使用当成文案、路由或平台验收完成。框架层LocaleController保持全局选择，实验中文边界不改写用户偏好。

参考：[Flutter官方国际化与局部Locale覆盖](https://docs.flutter.dev/ui/internationalization)。
