## 设计基准：参照电池插件，按能力域实现

参考的是 `packages/flutter_battery`，不是旁边独立旧检出 `/Users/forest/code/langGraph/flutter_battery`，也不把 `/Users/forest/code/flutter_battery` 的历史状态当现状。

借鉴能力查询与功能执行分离、类型化 Outcome/稳定原因码、有限等待、操作所有权、明确关闭状态、幂等释放、迟到结果隔离及 fake 注入。不要照搬电池的采样计时器、订阅模式或固定超时时长到认证/权限提示。设备等待和用户交互分别定义期限及取消语义。

每个能力域保持独立接口，原生操作只由插件/桥接包拥有；Forge session 负责交互状态和生命周期，UI 不直接操作 MethodChannel。不给所有硬件域引入全局门面、统一业务状态机或强制共用 Outcome 类。

通道负载视为不可信输入，先校验结构和字段；未知值明确表达 unknown/invalidData。无适配器、无能力、读取失败分开处理。参数编程错误与运行失败区分，不以宽泛 catch 隐藏程序缺陷。查询失败降级规则须与电池基准及各域契约一致。

一项原生操作明确 owner、operation id/epoch、并发策略和唯一终态；取消/超时应实际停止底层操作，或明确无法停止且隔离迟到回调，不能仅在 Dart Future 上加 timeout。dispose 不再更新 UI；取消、detach、engine 销毁不得留下无界等待；正常与异常路径都释放监听器/资源。

### P1 生物识别具体设计

1. 当前依赖为 Git `flutter_biometric v0.2.0`，锁定 `84f36aa567384ea83e9148822355dc12db72eeb0`。按 ADR 0019 默认收口到 `packages/flutter_biometric`，保留包名减小无关 import 改动；从该精确来源导入并保留 LICENSE/来源及本地变更记录，不改缓存、删除外部仓库或发布新版本。发现已有独立消费者/明确外部维护约定时，先记录事实再决定例外，不默认为本地升级外部仓库。
2. Android 使用 androidx 命名常量替换错误的设备凭据 magic number（当前写 2，官方设备凭据常量为 1）；核对真实回调与系统取消映射。校验 API29/30+ 的能力与策略差异。
3. 将“认证成功”和“本次认证方式是否可知”分开建模。macOS 凭据回退策略下无法可靠区分方式时应表达 unknown，不默认 biometric。模型/API 调整可实施；涉及按钮和允许策略变化先提交核心功能方案。
4. strong/weak 是强度，不能推导为指纹/面容独占；整体 canAuthenticate + 硬件特征不能保证某种生物特征已录入。能力模型记录能证明的事实，为界面纠正准备对照方案，不擅自删除现有实验入口。
5. 提供可明确结束的认证操作与取消契约，保证原生只回一次；处理并发、Activity 重建/detach、窗口退出。同步修复 BiometricSession initialize/authenticate/dispose。
6. 模块平台仍为 Android/macOS，其他平台保持统一不可用入口，不为通过测试扩大声明。

### P2 通知具体设计

1. NotificationSession 初始化、授权、投递及撤回增加操作所有权与销毁保护；失败应结束 loading，避免旧操作覆盖新会话。
2. MethodChannel 与 Outcome 解析覆盖错误顶层类型、缺字段、错误字段类型、未知状态；无效响应返回域内 invalidData。
3. Android 权限等待不得在 detach 时只丢弃 pendingPermissionResult；配置重建与永久 detach 分别设计，清理旧监听器，保证有界终态与重试。
4. 对齐 Android/macOS 权限事实、系统受理、实际可见投递之间的语义；不要把请求已提交直接表述为通知已显示，也不要推断拒绝后一定再次弹框。需要改变主要投递流程时先提交方案。

### P3 范围控制

- BLE 优先读取当前未提交的 client/scan/GATT 拆分，沿用或调整已有工作，不覆盖；迁移 `flutter_forge/bluetooth_system` 系统设置/已连接音频设备调用与 Android 适配至域包。保留第三方 universal_ble 的职责，避免仅为包数量重新包装全部功能。
- 电池是参考实现，也要定点核对其取消、first-sample timeout、关闭及错误处理；只有确认问题才修改，不为一致命名重写成熟代码。
- USB 枚举审计能力查询及逐条解析；保留当前 entryRestriction。USB 网络审计 FFI handle/socket/relay 的超时与幂等关闭。多窗口仅检查整改插件的每引擎注册和资源隔离，修复由本轮引入或证实的集成问题；不扩大为窗口系统重写。

## 验证与验收

先为确认的缺陷补能捕获错误的行为回归，再修改；不增加只镜像实现的测试。

- 插件层：通道请求/结果、畸形数据、无适配器、平台错误、unknown、并发、取消、重复关闭、detach 与迟到回调。原生常量/回调必须由原生测试或真实适配集成证明，Dart mock 不能代替。
- 调用方：查询中退出、认证/授权中退出、切换模块、双击、失败后重试、旧结果不覆盖新结果；小屏及大字体下关键操作可用。保留既有路由、教学内容与核心能力回归。
- 多窗口：主/分类窗口各自插件注册、独立操作与退出；单窗口 fake 测试不代表每引擎验证完成。
- 注册/依赖/模块/平台契约变化后，修改生成源并运行 `bash tool/generate_harness_ai_analysis.sh`；不得手改生成物。内部化后的插件测试须进入现有 workspace 自动遍历，不改门禁脚本语义来绕过。
- 实施后按现有规则执行 hot reload/restart（有运行应用时）及 `bash tool/quality_gate.sh`；无运行应用如实记录。执行受影响的 macOS/Android 构建，外加 Windows/Web 非回归构建（环境可用时）；平台不可用应保留未完成清单，不能标 PASS。
- 普通 CI 未提前编译原生插件是已识别缺口；可以准备路径触发构建/独立插件 CI 方案，但不改门禁语义，待用户显式授权 packaging_change 后实施。
