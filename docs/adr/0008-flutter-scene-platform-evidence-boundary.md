# ADR 0008: Flutter Scene 依赖与平台证据边界

| 属性 | 值 |
|------|-----|
| 状态 | accepted |
| 日期 | 2026-09-13 |
| 决策者 | forest |

## 上下文

Flutter Scene 在 1.0 前仍可能于次版本引入破坏性 API 变化，且声明的平台覆盖不能替代真实主机构建和运行证据。首个 3D 学习单元需要保持教学范围小、运行时依赖可替换，并避免把主机开关误写成平台验收。

## 决策

1. 应用将 `flutter_scene` 精确固定为 `0.23.0`，直接导入时同时声明 `vector_math` 直接依赖。
2. Flutter Scene API 仅由 `flutter_scene_3d` 的模块本地运行时边界接触；页面和测试通过该边界观察初始化、加载失败和控制行为。
3. 首期只渲染一个内建 `CuboidGeometry`，使用 `SceneView` 自带帧循环完成相机环绕；GLB、物理、定制着色器、后处理、场景编辑和高级材质延期。
4. macOS 与 Windows 主机按上游方式启用 Flutter GPU，但首期模块平台准入仅为 macOS。
5. Windows、Android、iOS 与 Web 保持目录可见且不可用；每个平台必须在独立任务中取得真实主机构建与运行证据后才能准入。

## 后果

- 依赖升级必须显式修改精确版本，并重新验证模块本地运行时边界。
- Flutter GPU 配置是运行前提，不构成模块平台 PASS。
- Widget 测试使用替代运行时，不建立复杂 GPU 测试框架，也不声称提供真实渲染证据。
