# 四端交互分工与原生窗口背景材质

状态：accepted，2026-10-21 用户确认全部推荐。本文定义实现规则；本轮实现及各平台验证范围见 [实施与 macOS 验收记录](../reports/PLATFORM_INTERACTION_MACOS_ACCEPTANCE-20261021.md)，不能从规则本身推定所有平台均已验收。

四端共享模块分类、稳定路由与支持声明，但按使用场景组织入口：macOS／Windows 面向长时间学习与键鼠实验；Web 面向浏览、链接直达、分享与交互实验；Android 优先快速查找概念和示例。iOS 仍为后续目标，不因本规则获得宿主或验收声明。

## 桌面页面与材质

基础导航页面覆盖工作台首页、分类目录、关于，以及后续新增的同类应用级页面。此分类按职责定义，不能将根路径下的教学模块误判为基础导航页面。基础页面默认使用原生窗口背景材质，快速打开沿用当前页面上下文。

进入教学模块及其子页面后，教学正文、实验区和侧栏使用实色；标题栏保留最低强度的系统材质或取色层次。最低强度不定义为跨平台统一 alpha 数值，以可读性和原生效果为准。教学模块退出并返回基础页面时恢复基础页外观。不可用模块说明页按教学入口使用实色。

桌面首次启动默认启用系统材质并跟随系统明暗，提供关闭入口。用户已明确保存的实色偏好继续有效；现有主题需迁移时保留明暗与实色选择。系统关闭透明效果、高对比度、原生能力缺失或初始化失败时回退实色。文字和控件本身不降低不透明度，不同时叠加高强度系统模糊与 Flutter 折射。

稳定性优先于两端视觉一致：macOS 优先验证系统 NSVisualEffectView 材质；Windows 11 优先验证 Mica，Windows 10 或能力不可用时使用实色。Mica 是壁纸取色的不透明材质，不作为透出其他窗口的半透明效果宣传或验收。Windows Acrylic 暂不作为默认方案，避免为追求相近透视效果引入旧版系统未公开 API 和已知拖窗问题。

原生窗口按钮、拖拽、缩放、双击、Snap、真实全屏和关闭语义继续遵循 ADR 0016。分类专注窗口采用相同页面规则，主题与材质命令只作用于所属窗口；独立创建、关闭和复用都必须验证。

## 插件评估与接入边界

现有 liquid_glass_easy 提供 Flutter 内部玻璃，不单独承担系统背景材质。flutter_acrylic 作为首个验证候选，其 macOS 能力依赖 macos_window_utils；依赖声明支持两端不等于与当前窗口宿主兼容。

首先完成两端原型，核实主窗口及 desktop_multi_window 子引擎的插件注册、窗口绑定、透明绘制链路、窗口创建前后配置时机、主题与系统设置响应。尤其检查当前 macOS 不透明窗口设置和 Flutter 自绘背景是否遮住系统材质，以及 Windows DWM 配置是否与已有窗口控制冲突。候选仅接入材质能力，现有 DesktopWindowHost 继续拥有窗口操作。若候选必须接管窗口控制或无法可靠绑定分类窗口，不将其直接纳入正式依赖；先记录适配差距再选择更窄的原生材质适配。

本轮源码评估确认 macos_window_utils 1.9.1 使用进程级静态 mainFlutterWindow，initialize/reset 会影响主窗口及控制器，不能直接满足每引擎分类窗口绑定。因此不新增 flutter_acrylic 依赖，采用上述允许的更窄适配：在既有 DesktopWindowHost 方法通道中接入每窗口 NSVisualEffectView，以及公开 DWM system backdrop；窗口控制归属保持不变。Windows 仅在公开接口成功时启用 Mica，旧版与失败路径回退实色。本轮未升级依赖；macOS 与 Windows 验证结论分别记录。

## Web 与移动入口

首页采用“搜索 → 分类 → 最近访问”的内容顺序，作者资料进入关于。最近访问只记录模块入口，不新增学习进度、账户同步或后台任务恢复。Web 依屏宽保留侧栏、Rail 与紧凑导航；移动采用首页、分类列表、教学详情三级结构，首页顶部常驻搜索，本阶段不新增底部标签栏。

Web／移动默认使用清晰实色表面，原生窗口材质只属于桌面宿主。Web 继续使用稳定 URL、浏览器前进／后退与用户显式选择的新标签页操作；移动保持应用内单窗口。模块限制继续由 module_registry 与统一守卫决定。

## 实施顺序与验证

1. 先验证原生材质候选与现有窗口宿主、多窗口、系统降级的兼容性，分别记录 macOS 与 Windows 结果。
2. 接入按页面职责选择的桌面表面规则与主题迁移，再调整 Web／移动首页及导航；本阶段优先修改 app 层。
3. 补页面切换、搜索返回、历史入口和窗口生命周期行为验证，执行现有质量门禁。桌面检查启动、缩放、主题、全屏与分类窗口；Web 检查深链、子路径部署、前进后退与显式新标签页；手机检查窄屏、软键盘、触摸与系统返回。各端构建和真实主机／真机操作分别报告。

## 搜索、返回与本期范围

四端统一检索模块标题、简介、分类及概念；同一会话从教学返回时保留检索词、分类位置与滚动位置。Web 的恢复与浏览器历史配合，不通过替换历史记录破坏前进／后退。最近访问持久保存模块入口，不恢复实验运行状态。

本阶段调整应用入口、导航、表面和阅读容器。教学模块内部内容与实验布局按模块后续优化；阻碍基本阅读或操作的溢出问题纳入本期修正。移动快速查阅复用同一份教学内容，不新增独立文章副本。

本决策替代 ADR 0016 的桌面默认实色与仅限应用内部透明的外观约定，以及 ADR 0012 的 Web／移动创作者默认首页与仅标题搜索约定；其余路由、窗口控制与生命周期边界继续有效。机器契约分别记录当前实现事实和已接受、尚待实施的方向；完成实施后再更新对应实现事实与任务状态。
