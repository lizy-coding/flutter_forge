# ADR 0013: 能力推导可用性与独立验证记录

状态：accepted

逐模块手工填写平台排除名单与分别维护验收说明，容易让能力策略、功能差异和历史报告失去同步。保留 ADR 0011 的平台快照、稳定路由与入口语义，将人工平台名单改为由项目能力适配规则推导。

生成器从模块依赖和模块目录的 imports/exports 发现能力需求，能力规则集中保存适配平台、理由代码与实现依据。模块只显式表达可选能力和产品级入口关闭意图；未知依赖列为待审阅，不从插件的平台宣传自动推断。生成的 `ModulePlatformSupport.excludedPlatforms` 保持应用侧兼容接口，功能差异使用同源的 `features` 策略。

逻辑测试、完整应用编译、指定模块真实执行和人工界面验收记录独立保存，均不影响可用性。工具执行后自动采集记录；人工按生成用例提供证据并登记一次。记录包含来源指纹、环境、提交与工作区状态，源码变化只令证据过期，不自动关闭模块。历史报告不自动迁移为当前 PASS。

## 后果

- 平台规则按能力共享，新增模块复用能力时无需再维护平台名单。
- 矩阵、机器契约、人工界面用例与应用策略由同一流水线生成。
- 适配规则与无法自动推断的视觉预期仍需维护，集中维护比重复记录更可审阅。
- 权限、设备连接和执行结果仍在模块内反馈，不动态修改路由。
- 界面用例来自行为测试与明确视觉预期；自动测试通过不能替代人工界面验收。
- 验证标识首先进入维护文档，应用目录暂不增加验收状态 UI。

操作入口见 [模块可用性维护](../module_availability/README.md)。
