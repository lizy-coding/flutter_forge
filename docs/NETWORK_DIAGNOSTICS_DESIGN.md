# 网络诊断模块设计

状态：首版产品范围已获用户整体批准，进入实现；平台接入、自动化检查与真实主机验收分别记录，不以此文档声明验收通过。

## 已确认范围

目标是稳定、方便使用的网络诊断工具。首发 macOS、Windows，后续兼容 Android、iOS，Web 不纳入模块范围。各平台后续分别完成能力接入和真实主机验收。

首版覆盖整体无法上网、指定网站或服务不可达、网络慢、延迟高及间歇性连接失败。局域网设备发现与设备协议诊断后续单独扩展。

用户可一键检测，也可选择故障现象或输入目标地址。界面先展示基本信息、结论和建议，支持展开查看检测证据、耗时与原始结果，不要求用户先理解网络术语。

第一版只检测、解释并给出操作建议，不修改 DNS、不重置网络或修改其他系统设置；提供重新检测与复制报告操作。

使用多个可替换的内置检测目标，并支持自定义。报告显示实际检测目标，将单个目标不可达与整体网络异常分开表达。具体目标见首版实施设计。

首版只做延迟、请求耗时与一段时间内的失败情况观测，不包含下载／上传带宽测速。界面明确这些观测不能代表带宽测速结果，有限观察也不能保证捕获所有间歇性故障。

报告只保留当前会话，不保存跨会话历史；用户可预览报告并隐藏敏感信息后复制，默认隐藏规则见首版实施设计。

首版暂缓 AI／GenUI 接入。核心检测与基础结论不依赖模型服务或密钥；后续是否增加 AI 解释或动态追问，应由实际使用需求决定。

## 固定 UI 与 GenUI

首版采用固定 UI。当前目标是稳定、方便使用的网络工具，已确认的检测入口、结果摘要与展开详情可由确定性界面承载，暂不引入模型生成界面的等待、依赖与验证成本。不能将使用 SDK 或按固定规则生成组件树视为模型生成 UI 的收益证据。

检测能力负责产生证据；基础诊断规则解释证据；固定 UI 展示结论、建议和可展开详情。若后续引入 GenUI，它应基于已实现的能力和组件组织交互，不能自行获得网络检测能力，也不能将推测展示为测量事实。

## 首版实施设计

用户主动发起检测后，先查询操作系统与非回环网卡地址，再执行 DNS 解析、TCP 连接以及 HTTP(S) HEAD。每个阶段最多三秒，阶段失败后下游标为未执行；TCP 目标止于端口连接。网卡信息获取失败不阻止目标检测，未采集的信息明确标记未知，不推断 Wi-Fi 名称、默认网关或系统 DNS 配置。

默认目标为 `https://www.baidu.com/` 与 `https://www.bing.com/`，只作为可替换的公共网站，不依赖项目自建端点，也不承诺地区可达性或服务 SLA。用户可以编辑并完全替换目标。支持 HTTP(S) 地址或 `tcp://主机:端口`，最多四个不同目标，不接受账号、查询参数或片段，避免携带凭据。HTTPS 使用正常证书校验。

快速模式一轮；慢／间歇失败模式五轮，轮间隔一秒。每轮最多四个目标并行，整个会话上限 60 秒。用户取消、会话超时或离开页面时关闭活动连接和 HTTP 客户端，已完成观测可保留；操作系统 DNS 查询无法强制终止，其迟到结果不再更新页面。

请求使用应用直接连接，不读取系统代理，不绕过 VPN 路由。HTTP 使用独立连接，耗时包含连接与 HTTPS 握手，不能与单独 DNS/TCP 阶段相加作为同一请求的时序。HEAD 不跟随重定向、不下载正文；收到 4xx/5xx 代表服务响应并需检查业务或权限，不能记为网络不通。服务拒绝 HEAD 时不自动回退下载。

报告按目标与轮次展示阶段结果、解析地址、响应状态和耗时，计算已完成观测的连接／请求失败率与成功末阶段平均耗时，不称为丢包率、链路 RTT 或带宽。取消或未完成的观测不进入失败率。全部检测目标失败时仅给出候选排查方向，不判定整体断网或确定根因。

报告预览默认隐藏目标完整地址、网卡名称、本机及解析 IP；取消隐藏后可复制原始字段。报告仅在页面会话内保存，不持久化、不上传模型服务。

定向测试覆盖真实本机 HTTP/TCP、超时、取消、迟到结果、状态规则、输入边界与报告隐藏，以及紧凑界面操作。macOS 与 Windows 的真实主机验收独立记录。

当前实现与验证范围见 [实施记录](reports/NETWORK_DIAGNOSTICS_IMPLEMENTATION-20261023.md)。

## 实施边界

模块使用稳定路由 `/network-diagnostics`，归入网络与平台分类，复用教学模板。入口支持通过桌面诊断适配规则推导，Android/iOS 保留未来兼容方向，Web 不做；未开放的平台使用统一不可用说明页。学习状态先保持 pending，与平台支持分别表达。产品首发范围不是构建通过或真实主机验收事实。

## VPN 与劫持线索检测

点击检测后额外执行一次随机绝对 `.invalid.` 名称的系统解析（RFC 6761 §6.4），不连接解析出的地址。意外返回地址标为可疑，可能来自 DNS 改写、代理 Fake-IP 或本机配置；系统解析异常不能可靠区分 NXDOMAIN、断网和解析器故障，因此显示无法判断。未返回地址也不能证明其他域名没有被改写。查询沿用单阶段超时、会话取消与迟到结果隔离。

VPN 检查依据有地址的网卡名称识别常见 utun/tun/tap/ppp/wg、WireGuard/Wintun/OpenVPN 等隧道线索。发现线索不等于 VPN 已连接；未发现不等于未使用 VPN。当前不读取系统 VPN 会话或路由表，不能确认默认路由、分流与指定目标是否经过 VPN。macOS 系统服务也可能创建 utun。

每个 HTTP(S) 目标展示系统 TLS 校验、重定向与明文响应的证据边界。TLS 握手／证书失败及 HTTPS 降级 HTTP 标为可疑，不能独立判定劫持；跨主机跳转仅提示核对，普通跳转不标成劫持。保持证书校验、不跟随跳转、不下载正文。没有证书固定、可信响应基线、独立 DNS 对照或认证门户内容验证，因此不宣称完成全面劫持检测。

上述状态独立于连通性，不改变 TCP／HTTP 成功与失败率含义。UI 与报告同时展示；报告不增加原始网卡名称、异常解析 IP 或 Location，避免隐藏模式泄露跳转凭据。
