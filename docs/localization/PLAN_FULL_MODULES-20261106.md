# 中英文操作界面落地方案

状态：实施中；2026-11-06。产品范围与行为已确认，基础包和首批框架接入已实现；全部模块操作文案与平台验收尚未完成。

## 已确认

- 官方 flutter_localizations + gen_l10n + ARB。
- 全部注册模块操作界面双语，教学正文保留中文。
- 当期覆盖应用框架、导航、路由页面及全部模块操作界面，建立独立可复用 Flutter package，供 Forge 与其他 Flutter 应用使用；暂不公开发布，不新增原生通道。业务 ARB 由各应用持有，持久化和多窗口传输由宿主接入。URL 和路由 ID 保持稳定，仅翻译展示名称。
- 新安装与旧用户升级在无显式语言偏好时均默认跟随系统；保留手动选择并持久化的能力。
- 翻译目录标题/简介、按钮、表头/图例、状态/错误/权限提示、章节标题及可执行的澄清选项。长篇讲解、练习正文、示例文章、代码与原始日志保留原文；英文模式标明教学正文为中文。隐私入口与数据控制说明翻译，政策全文暂保留中文并标明。
- 所有现有平台共用入口和模块代码当期接入双语，Android 真机为本次发行关口；macOS/Windows/Web 原生及多窗口专项单独记录，不据 Android 结果宣称其已验收。iOS 仅有平台模型，未建立宿主，不宣称完成宿主接入。
- 按钮、标签页、表头可用人工定义短标签；完整语义名称及提示保留。正文换行，权限和关键错误不简写。
- 原定 2026-11-07 Android 发布延期，等待上述范围完成，不承诺新的发布日期。

## 当前事实与影响

注册表当前有 35 个模块：基础 6、异步 3、状态 3、UI 8、弹窗与列表 4、平台 11；数量不是 Android 可运行模块数量。模块元数据源在 tool/generate_agent_indexes.js，经 tool/agent_indexes/routes.js 生成 module_manifest.dart，不手改生成物。

App 和 CategoryWindowApp 分别持有 MaterialApp.router；语言变化需要保留 Router、页面与实验状态。当前主题偏好控制器及窗口同步机制可作为实现参考，不新增状态管理框架。

shared/learning 同时包含章节标题、复制提示等操作文案和调用方传入的教学内容。forge_articles、module_discovery_replay、WebView 内置 HTML 也混有控制文案、提示与教学数据，实施前逐项划界。隐私政策有独立生成源 docs/privacy/policies.json，不在 ARB 复制第二份正文。

## 实施顺序

1. 建立 35 模块覆盖清单，区分操作文案、中文教学正文、代码标识符、外部/系统内容；定下术语与短标签。
2. 建立 workspace 内可复用本地化包，封装语言偏好模型、系统语言解析与通知接口；应用拥有业务 ARB 和生成 delegate。采用普通 Flutter package，不新增原生通道，不依赖 Forge 业务模块或路由。
3. 当期接入主应用和分类窗口 delegates、导航/路由页面展示、shared 教学组件与模块元数据；同步生成源。使用稳定模块标识和 URL，路由显示名称双语。建立持久化及切换不丢会话的测试。
4. 以三棵树、弹窗、3D 等代表模块验证接口，再按六分类迁移全部模块；不让桥接包反向依赖应用翻译类。
5. 检查会话缓存的提示和错误，避免切语言后遗留旧语言；外部数据不强制翻译。
6. 分别完成语言、窄布局、平台与发行候选包验收，执行既有质量门禁；新检查不擅自改动门禁脚本语义。

## 后续维护约束

- 每个新增/修改操作文案同步提供中文、英文、必要的短标签与完整名称。
- ARB 是可翻译操作文案的唯一源；生成元数据仅引用稳定映射，避免复制多份人工维护译文。
- 语义 key 与类型化参数；不以中文原文作 key，不拼接数量单位。
- 测试检查缺失 key、占位符一致性、语言切换状态保持和英文长文本；人工检查翻译含义与短标签可理解性。
- 公共业务包返回稳定状态/错误标识，由展示层翻译；必须自行展示界面的独立包采用自身文案边界，不能依赖 app/。

## 包边界与交付建议

建议命名 packages/forge_localization；名称是实施建议，不代表已创建。公共 API 只表达语言偏好、支持语言集合、系统语言解析、当前有效 Locale 与变化通知，不直接引用业务 ARB、路由、SharedPreferences 或桌面窗口实现。

宿主负责加载/保存偏好、系统语言变化的生命周期监听及跨引擎消息。应用在 lib/l10n 维护自身文案，主应用与分类窗口复用同一 delegates 配置。通用包不建立另一套字符串查找或翻译生成器，仍由官方 gen_l10n 完成文案生成。

独立包以测试证明可脱离 Forge 业务启动；所有新增 workspace 契约与依赖同步生成源，遵循包目录规则。不增加远程翻译服务或运行时下载，保持离线发行能力。

## 已确认的交互规则

1. 语言入口与解析：关于页固定显示“语言 / Language”；跟随系统按系统语言优先列表匹配中/英，中文变体映射简中，无支持语言回退中文；手动选择不受系统变化覆盖。
2. 搜索：任意界面语言都检索中英元数据及原有技术术语，结果显示当前语言；切换保留原查询词，不自动翻译用户输入。
3. 状态：语言即时切换，不重建路由/任务；所有窗口共享偏好。当前状态和新提示随语言更新，原始日志与外部内容保留；持久化失败明确提示，不能伪报已保存。

## 公共接口与状态一致性设计

以下为职责接口草案，实施时可调整名称，不引入新的状态管理框架。

| 接口 | 输入/输出与责任 |
| --- | --- |
| LocalePreference | system 或显式语言标签；持久化标签，不持久化枚举序号 |
| LocalePolicy | supportedLocales、fallbackLocale 与系统语言列表，解析有效 Locale；不硬编码 Forge 的语言集合 |
| LocaleController | preference、effectiveLocale、变化通知；接收系统语言列表和远端偏好 |
| 宿主偏好 adapter | 读取/写入偏好，处理无值、损坏和保存失败；包不直接依赖存储插件 |
| 宿主窗口 adapter | 主窗口协调写入与广播，子窗口提出变更并接收快照，携带修订号避免旧消息覆盖和循环广播 |

Forge 的配置为 system/zh/en，系统中文变体映射简中，按系统优先列表选首个支持语言；若没有支持项则回退中文。手动选择仍记录系统变化，切回 system 时立即采用最新系统语言。

保存采用串行最新意图处理：用户选择立即反映在界面与活动窗口，保存失败显示未保存状态并可重试；不能把失败状态报告为持久保存成功，不能让较早写入覆盖新选择。冷启动读取失败回退 system，并暴露可观察错误。远端应用更新不再次发起同一广播。

LocaleController 和 Router 均保持稳定实例；语言变化只触发依赖它的展示更新。禁止给根 Widget 按 Locale 换 Key、重建 ProviderScope 或重启实验。通过状态标识与参数展示当前状态；原始日志、已经发生的外部事件不重写。切换语言不触发网络请求、外设操作或重新执行实验。

## 文案、注册表与包的依赖边界

- 应用业务资源建议为 lib/l10n/app_zh.arb 与 app_en.arb，中文作为模板，采用领域前缀组织 key；生成文件直接位于源码目录，不使用旧 flutter_gen 虚拟包。
- 注册源继续维护模块 ID、稳定路由与完整元数据结构。显示字段使用生成的类型化映射从 AppLocalizations 取得；中文展示文本逐步迁入 ARB，原生成源不再维护第二份人工中文副本。
- 概念保留稳定标识，显示标签及双语搜索词分别取得；搜寻支持标题、简介、分类、概念与原有技术词。中英文索引按稳定模块 ID 去重，不将翻译后的标题作为路由或历史主键。
- Agent JSON 契约继续保持机器语义；如需中文维护标题，由生成器读取中文资源派生，不能手改生成契约。更新生成源后执行 bash tool/generate_harness_ai_analysis.sh。
- shared/learning 可依赖应用 lib/l10n，但不能依赖 app/。独立业务包不引用应用 l10n：返回状态/错误代码与参数，应用展示层翻译；独立包自行渲染的控件允许由调用方注入类型化文案。
- 对章节说明、教学文章、演示数据和回放按已确认边界分类。控制按钮、澄清选项和操作错误双语，解释性正文保留中文并显示语言提示；避免对任意返回字符串做运行时替换。
- 自定义原生窗口标题同步当前展示文本；系统权限对话框使用系统语言。Web 首帧前加载壳需单独接入语言解析策略，使用同源本地资源；不假定 Flutter delegates 能控制 HTML 加载壳。

## 维护成本与取舍

| 方案 | 初期成本 | 新模块/文案维护 | 长期兼容责任 |
| --- | --- | --- | --- |
| 官方 gen_l10n + 本次薄封装（已选） | 中：ARB 提取、接口和宿主 adapter | 两种文案、参数、必要短标签、双语检查；框架类型化访问减少 key 拼写与参数错误 | SDK/intl 兼容由版本锁定管理；团队维护偏好和窗口 adapter，不另养翻译生成器 |
| 官方 gen_l10n 仅写在 App 内 | 较低 | 翻译成本相同；第二个 App 需要复制语言逻辑 | 单 App 便宜，但不满足独立复用目标 |
| slang | 中 | 命名空间/分文件方便；正文校对与界面验收成本仍存在 | 增加第三方生成器和库的升级验证，迁移已有接口有成本 |
| easy_localization | 较低到中 | JSON 接入方便；字符串 key/参数及资源覆盖需要额外约束，可用生成 key 辅助 | 增加加载/运行库适配；翻译与布局验收不会因此减少 |
| 自建 Map 或逐处语言条件 | 初期低 | 文案、回退、参数及漏翻维护成本高 | 全部查找与翻译规则由项目自己维护，不采用 |

以上是结构性成本判断，不是耗时或性能实测。此次不翻译教学正文，减少翻译量，但35模块操作、搜索和多窗口状态仍需逐项核实。第一批先计量真实迁移时间，随后按剩余模块复杂度估算工期，不以“一个开关”承诺发布日期。

后续一次文案变更的固定流程：修改两份 ARB及参数描述 → 官方生成 → 定向行为/布局检查 → 现有门禁；增加模块时同步注册映射及双语清单。人工审核重点是术语、短标签和提示含义，自动检查重点是缺失/冗余 key、参数一致性、状态保持及溢出。新检查放入既有自动收集的测试或作为独立命令，不修改质量门禁/CI脚本语义。
