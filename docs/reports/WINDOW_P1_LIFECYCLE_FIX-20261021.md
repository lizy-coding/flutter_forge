# 多窗口 P1 生命周期与配置恢复

日期：2026-10-21。基线 `dev / eb500f5` 加未提交工作区；不是已发布版本验收。本次承接可用性评估中的三项 P1，保留原有导航、主题、材质及其他工作区改动。

## 实施结果

### 启动就绪和失败清理

- 分类窗口隐藏创建；等待子窗口 Dart 页面完成构建并完成原生通知握手，Windows 再检查子引擎首帧屏障，之后显示窗口并记入可复用目录。显示和首帧屏障仍不等同于真实鼠标交互或 GPU 完成。
- Windows 注册窗口定义、插件与所属宿主后才安装首帧回调；默认可见窗口也延后到首帧显示。回调按窗口 ID 查找对象，不捕获已关闭窗口的裸指针。
- Windows 原生创建失败返回 `WINDOW_CREATION_FAILED`；Dart 对空 ID 执行 Release 有效的检查，不依赖 assert。
- 创建、就绪和显示各阶段有 15 秒上限。超时返回错误；迟到的创建结果仍会关闭。失败窗口不进入可复用目录，已知清理失败的窗口必须先完成清理，才允许该分类再次创建。
- `closeNative()` 不只等待关闭回复，还在 3 秒预算内确认原生库存已移除；窗口在请求前自行关闭时，仅在库存确认其不存在后将清理视为完成。
- macOS 隐藏窗口显式启动 engine，避免依赖不可见窗口的 viewDidAppear。Windows／macOS 原生库存通知等待当前引擎的 `markReady()`，避免向未启动的子引擎主动发消息。

### Windows 有序退出和回收

- 主 controller 销毁前执行幂等 `DesktopMultiWindowShutdown()`：禁止新建、停止窗口库存广播、同步关闭所有受管子窗口并销毁子引擎，再继续主引擎销毁。
- 子窗口销毁流程幂等，清理时仍不调用失效 messenger。
- 主消息循环每次 DispatchMessage 返回后回收已关闭的窗口对象，不再等待下一次创建窗口，也不在窗口自身回调栈内删除对象。
- 消息循环结束后再次 shutdown 并销毁主窗口，确保在 CoUninitialize 前完成引擎释放。内部包示例同步接入清理入口；示例本来的“主窗口关闭不立即退出”语义保留。

### 宿主配置恢复

- 仅在有效配置回复成功后确认缓存；失败不会永久去重同一个请求。
- 单次配置 2 秒超时，同一配置最多尝试 3 次，间隔 200ms；耗尽后显示底部失败提示和“重试”入口，用户可在当前页面重试。
- 配置变化时发送最新值；迟到回复不能覆盖新状态。切回先前已保存配置时，也会在旧请求完成后重新应用最新值。
- Widget 销毁时取消超时与重试 Timer、释放等待，不在已销毁对象上更新状态。
